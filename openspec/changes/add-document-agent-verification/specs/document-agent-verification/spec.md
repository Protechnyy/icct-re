## Purpose

在并发抽取之后，由一个 agent 在整篇文档范围内核查抽取出的关系：自己规划要查什么，通过工具查原文和实体，并在一篇文档的处理过程中记住已确认的结论，最终产出更可靠的关系列表。

## ADDED Requirements

### Requirement: 核查阶段的位置与开关
系统 SHALL 在所有 batch 抽取完成并做完规则去重之后、生成最终结果之前运行文档级核查阶段。该阶段 MUST 可通过配置整段关闭，且默认关闭。

#### Scenario: 开关关闭
- **WHEN** 核查阶段被配置为关闭，并处理一篇文档
- **THEN** 最终关系列表与未引入本能力时完全一致，且不发生任何核查用的模型调用

#### Scenario: 开关开启
- **WHEN** 核查阶段被配置为开启，并处理一篇抽取出至少一条关系的文档
- **THEN** 系统在规则去重之后运行核查阶段，最终关系列表取核查后的结果

#### Scenario: 没有可核查的内容
- **WHEN** 核查阶段开启，但文档没有抽取出任何关系
- **THEN** 系统跳过核查阶段，并在结果中标明已跳过

### Requirement: 由模型规划核查任务
核查阶段 SHALL 先让模型产出一份任务清单，再开始执行。提供给模型的输入 MUST 包含关系图概览（实体、各小节的关系数量）和规则标出的疑点；疑点只作为线索，模型 MUST 能够增删和排序任务。每个任务 MUST 属于以下类型之一：核查证据、归一实体、检查小节漏抽。

#### Scenario: 规划产出任务清单
- **WHEN** 核查阶段开始
- **THEN** 系统得到一份有序的任务清单，每个任务带有类型、目标和理由

#### Scenario: 任务目标必须存在
- **WHEN** 模型规划的某个任务指向不存在的关系、实体或小节
- **THEN** 系统丢弃该任务并记录原因，其余任务照常执行

#### Scenario: 任务数量超限
- **WHEN** 模型规划的任务数超过配置的上限
- **THEN** 系统只保留排在前面的任务，并在结果中记录被截掉的数量

#### Scenario: 规划失败
- **WHEN** 规划调用出错或返回无法解析的内容
- **THEN** 系统退回为直接使用规则标出的疑点作为任务清单，并在结果中标明规划已降级

### Requirement: 用工具循环执行任务
对每个任务，系统 SHALL 让模型在一个循环中自行决定调用哪些工具、调用几次、何时结束。每个任务只暴露与其类型相关的工具，数量 MUST NOT 超过 5 个。循环 MUST 有步数上限。

#### Scenario: 模型自行结束
- **WHEN** 模型在某一步不再调用工具并给出结论
- **THEN** 该任务结束，状态为已完成，结论被记录

#### Scenario: 达到步数上限
- **WHEN** 某个任务的循环达到步数上限仍未结束
- **THEN** 系统终止该任务，状态为未完成，该任务已生效的修改保留，尚未涉及的关系保持原样

#### Scenario: 工具调用出错
- **WHEN** 模型调用了不存在的工具或传入了不合法的参数
- **THEN** 系统把错误信息作为工具结果返回给模型，由它继续，该步计入步数

### Requirement: 文档内记忆
系统 SHALL 在一篇文档的核查过程中维护一份记忆，至少包含实体别名表和已确认的结论，并在执行每个任务时提供给模型。记忆 MUST NOT 跨文档保留。

#### Scenario: 后续任务使用先前结论
- **WHEN** 先前的任务已确认两个名称指向同一实体，后续任务涉及其中一个名称
- **THEN** 后续任务的输入中包含这一结论

#### Scenario: 文档之间互不影响
- **WHEN** 一篇文档处理结束后开始处理另一篇文档
- **THEN** 新文档的核查从空记忆开始

### Requirement: 资源上限
系统 SHALL 对单篇文档的核查阶段设置模型调用次数上限和总时长上限，并对核查阶段的模型调用单独限制并发，默认串行。

#### Scenario: 调用次数或时长耗尽
- **WHEN** 核查阶段的模型调用次数或总时长达到上限
- **THEN** 系统停止执行剩余任务，已完成任务的修改保留，剩余任务标记为未执行，结果标明为部分完成

#### Scenario: 默认并发
- **WHEN** 未显式配置核查阶段的并发数
- **THEN** 同一时刻最多只有一个核查用的模型调用在进行

### Requirement: 失败不影响任务结果
核查阶段的任何失败 MUST NOT 导致文档处理任务失败。

#### Scenario: 核查阶段整体失败
- **WHEN** 核查阶段因模型服务不可用或内部错误而无法继续
- **THEN** 最终关系列表取核查之前的规则去重结果，任务状态仍为成功，结果中标明核查失败及原因

#### Scenario: 单个任务失败
- **WHEN** 某一个任务执行出错
- **THEN** 该任务标记为失败，其余任务继续执行

### Requirement: 每条关系带有核查状态
最终结果中的每条关系 SHALL 带有核查状态，取值为：未核查、已确认、已更正、新增。被删除的关系 MUST NOT 出现在最终关系列表中，但 MUST 连同删除理由保留在结果的核查部分。原有的关系字段 MUST 保持不变。

#### Scenario: 未被任何任务涉及的关系
- **WHEN** 一条关系没有被任何核查任务涉及
- **THEN** 它原样出现在最终关系列表中，状态为未核查

#### Scenario: 被删除的关系
- **WHEN** 一条关系在核查中被删除
- **THEN** 它不出现在最终关系列表中，但可以在结果的核查部分查到其原始内容和删除理由
