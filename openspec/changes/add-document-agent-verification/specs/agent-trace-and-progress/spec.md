## Purpose

让使用者看得见 agent 做了什么：处理过程中能看到任务清单和当前进展，处理结束后能查到每条关系被核查的完整过程和依据。

## ADDED Requirements

### Requirement: 记录核查轨迹
系统 SHALL 记录核查阶段的每一步，包括规划结果、每次工具调用（工具名、参数、结果摘要）、每个任务的结论，以及各步的耗时。工具结果摘要 MUST 有长度上限。

#### Scenario: 轨迹内容完整
- **WHEN** 核查阶段完成一个调用了若干次工具的任务
- **THEN** 轨迹中按顺序包含该任务的每次工具调用和最终结论

#### Scenario: 结果过长
- **WHEN** 某次工具调用返回的内容超过摘要长度上限
- **THEN** 轨迹中保存截断后的内容，并标明已截断

### Requirement: 轨迹随结果落盘
核查轨迹和核查摘要 SHALL 作为任务结果的一部分保存，并通过现有的结果接口返回。核查摘要 MUST 包含：阶段状态（完成、部分完成、失败、跳过）、任务总数与各状态的数量、已确认、已更正、新增、删除的关系数量、合并的实体数量、模型调用次数和总耗时。

#### Scenario: 查看已完成任务的结果
- **WHEN** 调用方获取一个已完成、且开启了核查的任务的结果
- **THEN** 结果中包含核查摘要和完整轨迹，原有字段保持不变

#### Scenario: 核查关闭
- **WHEN** 调用方获取一个未开启核查的任务的结果
- **THEN** 结果中的核查部分标明未开启，其余内容与引入本能力之前一致

### Requirement: 处理过程中上报进展
核查阶段运行期间，系统 SHALL 把进展写入任务状态，使状态接口能返回：当前处于核查阶段、任务清单的总数与已完成数、正在处理的任务、以及最近的若干条事件。

#### Scenario: 规划完成后
- **WHEN** 规划完成、任务尚未开始执行
- **THEN** 状态接口返回任务总数和任务清单

#### Scenario: 任务执行中
- **WHEN** 核查阶段正在执行第 N 个任务
- **THEN** 状态接口返回已完成的任务数、当前任务的描述和最近的工具调用事件

#### Scenario: 事件数量受限
- **WHEN** 核查阶段已产生大量事件
- **THEN** 状态接口只返回最近的若干条，完整记录在任务结束后通过结果接口获取

### Requirement: 前端展示核查过程
前端 SHALL 在任务处理中显示核查阶段的名称、任务进度和最近的事件；在结果页显示核查摘要，并允许查看任意一条关系的核查过程。

#### Scenario: 处理中
- **WHEN** 用户查看一个正处于核查阶段的任务
- **THEN** 界面显示已完成任务数与总数，以及最近几步在做什么

#### Scenario: 查看单条关系的核查过程
- **WHEN** 用户在结果页选中一条被核查过的关系
- **THEN** 界面显示该关系的核查状态、涉及它的任务、调用过的工具和最终结论

#### Scenario: 查看被删除的关系
- **WHEN** 用户在结果页查看核查摘要
- **THEN** 可以看到被删除的关系列表及各自的删除理由

#### Scenario: 核查未开启
- **WHEN** 用户查看一个未开启核查的任务
- **THEN** 界面不显示核查相关内容，其余展示不受影响
