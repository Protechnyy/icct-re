## Purpose

定义核查 agent 可以使用的工具：用来查阅当前文档原文和已抽取实体的只读工具，以及用来修改关系图的动作工具，并规定动作必须满足的原文依据约束。

## ADDED Requirements

### Requirement: 工具只作用于当前文档
所有工具 SHALL 只读取和修改当前正在处理的这一篇文档及其关系图，MUST NOT 访问其他文档、文件系统或网络。

#### Scenario: 查询范围
- **WHEN** agent 调用任何只读工具
- **THEN** 返回内容只来自当前文档的原文和当前文档已抽取的关系

### Requirement: 检索原文
系统 SHALL 提供按关键词检索原文的工具，输入为查询文本，返回按相关度排序的段落，每个结果带有小节编号、页码和段落原文。返回数量 MUST 有上限。

#### Scenario: 有命中
- **WHEN** agent 用文档中出现过的词检索
- **THEN** 返回包含该词的段落，并带有各自的小节编号和页码

#### Scenario: 无命中
- **WHEN** 查询文本在文档中没有任何相关段落
- **THEN** 返回空结果并明确说明没有命中，不返回错误

### Requirement: 读取小节
系统 SHALL 提供按小节编号读取整节原文的工具。

#### Scenario: 小节存在
- **WHEN** agent 用存在的小节编号调用
- **THEN** 返回该小节的标题、原文和页码范围

#### Scenario: 小节不存在
- **WHEN** agent 用不存在的小节编号调用
- **THEN** 返回说明该编号不存在的信息，并列出可用的小节编号

#### Scenario: 小节过长
- **WHEN** 小节原文超过单次返回的长度上限
- **THEN** 返回截断后的内容，并明确标出已截断

### Requirement: 定位证据
系统 SHALL 提供定位证据的工具，输入为一段引文，返回它在原文中的位置（小节编号、页码、所在段落）。比较时 MUST 忽略空白字符的差异。

#### Scenario: 精确命中
- **WHEN** 引文在原文中存在
- **THEN** 返回所有命中位置的小节编号、页码和所在段落

#### Scenario: 没有精确命中
- **WHEN** 引文在原文中不存在
- **THEN** 明确返回未命中，并给出原文中最接近的若干句子供参考

### Requirement: 查询实体
系统 SHALL 提供查询实体的工具，输入为实体名称，返回该实体已知的别名、出现的小节、以及它参与的关系。

#### Scenario: 实体已知
- **WHEN** agent 查询一个在关系图中出现过的名称
- **THEN** 返回其别名、出现的小节和相关关系

#### Scenario: 实体未知但有相近名称
- **WHEN** 查询的名称不在关系图中，但存在写法相近的实体
- **THEN** 返回未找到，并列出相近的实体名称

### Requirement: 修改动作必须有原文依据
更正证据、补充关系这两类动作 SHALL 要求提供证据引文，且该引文 MUST 能在当前文档原文中定位到，否则动作被拒绝。合并实体时，保留的规范名称 MUST 在原文中出现过。

#### Scenario: 证据可定位
- **WHEN** agent 提交的更正或新增关系带有能在原文中定位到的证据
- **THEN** 动作生效，关系的来源小节和页码按定位结果更新

#### Scenario: 证据无法定位
- **WHEN** agent 提交的更正或新增关系所带的证据在原文中找不到
- **THEN** 动作被拒绝，关系图不变，拒绝原因作为工具结果返回给 agent

#### Scenario: 规范名称不在原文中
- **WHEN** agent 合并实体时指定的规范名称在原文中没有出现过
- **THEN** 合并被拒绝，关系图不变

### Requirement: 删除必须说明理由
删除关系的动作 SHALL 要求给出理由。

#### Scenario: 带理由删除
- **WHEN** agent 删除一条关系并给出理由
- **THEN** 该关系从最终列表中移除，其原始内容和理由被保留

#### Scenario: 缺少理由
- **WHEN** agent 删除关系但没有给出理由
- **THEN** 动作被拒绝，关系图不变

### Requirement: 合并实体的效果
合并实体的动作 SHALL 把所有别名在关系图中统一替换为规范名称，并把这一对应关系写入文档内记忆。合并后产生的完全重复的关系 MUST 被去重。

#### Scenario: 合并生效
- **WHEN** agent 把若干别名合并到一个规范名称
- **THEN** 关系图中以这些别名为头实体或尾实体的关系都改用规范名称，重复的关系只保留一条

### Requirement: 新增关系有数量上限
单个任务中补充关系的数量 SHALL 有上限。

#### Scenario: 超出上限
- **WHEN** agent 在一个任务中补充的关系数达到上限后继续补充
- **THEN** 后续的补充动作被拒绝，并告知已达上限
