# Spec Delta

## Purpose

用户能够从工作台顶部编辑当前使用的一组模型 API 地址、Key 和模型名称，在保持原页面操作上下文的同时，明确区分默认配置、已保存设置、正在编辑的内容和保存结果，并在读取或保存失败时继续完成设置。

## ADDED Requirements

### Requirement: 顶部入口使用统一的图标文字按钮

系统 SHALL 在服务状态右侧保留 `Qwen / vLLM` 入口，并采用与顶部 `Skills` 一致的机器人图标文字按钮。字号、文字颜色、图标间距、按钮内边距、悬停及键盘焦点效果 SHALL 保持一致，服务状态和按钮之间 SHALL 保留分隔线。入口 SHALL 表达其打开对话框的作用及当前打开状态。

#### Scenario: 查看与使用顶部按钮
- **WHEN** 用户查看顶部模型设置入口，使用鼠标或键盘访问按钮
- **THEN** 按钮展示左侧机器人图标和右侧 `Qwen / vLLM` 文字，样式及操作反馈与 Skills 按钮一致，并能被识别为打开设置对话框的按钮

### Requirement: 从顶部打开模型设置弹窗

系统 SHALL 通过顶部 `Qwen / vLLM` 入口在当前页面上打开模型设置弹窗，并保留原页面、已选择任务和未提交的页面输入。系统 MUST 不切换到独立设置页面。关闭弹窗后 SHALL 继续显示打开前的页面。

#### Scenario: 在任务中心打开设置
- **WHEN** 用户在任务中心选择任务并点击顶部模型设置入口
- **THEN** 系统显示设置弹窗，原任务选择和上传文件列表保持不变

#### Scenario: 在 Skills 页面打开设置
- **WHEN** 用户在 Skills 页面打开并关闭模型设置弹窗
- **THEN** 系统继续显示原 Skills 页面及其已有状态

### Requirement: 读取当前单组配置

弹窗每次打开时 SHALL 读取当前已保存的单组配置，并展示 API 请求地址、当前生效模型、默认模型及后端名称、Key 是否已配置。读取完成前 SHALL 显示加载状态并禁止保存；读取失败时 SHALL 显示原因并提供重新读取操作。

#### Scenario: 成功读取配置
- **WHEN** 配置读取成功
- **THEN** 弹窗显示当前 API 请求地址、生效模型名称、默认模型名称和后端信息，并以“已配置”或“未配置”表达 Key 状态

#### Scenario: 读取失败后重试
- **WHEN** 读取接口返回错误或无法连接，用户随后点击重新读取
- **THEN** 弹窗保持打开，展示读取错误并重新请求配置，成功后允许编辑

### Requirement: 编辑模型名称并恢复默认配置

设置弹窗 SHALL 提供可编辑的模型名称字段，初次读取时显示当前生效名称，并说明配置默认名称。用户保存自定义名称后，系统 SHALL 保留并显示该名称；用户清空名称并保存时 SHALL 使用配置默认名称。

#### Scenario: 使用默认模型名称
- **WHEN** 当前没有自定义模型名称，用户打开设置
- **THEN** 模型名称字段显示配置默认名称，保存其他设置时主模型继续使用默认名称

#### Scenario: 保存自定义模型名称
- **WHEN** 用户输入非空模型名称并保存后重新打开设置
- **THEN** 字段显示该自定义名称，主模型后续请求使用该名称

#### Scenario: 清空自定义名称
- **WHEN** 用户清空模型名称并保存后重新打开设置
- **THEN** 字段恢复显示配置默认名称，主模型后续请求使用该默认名称

### Requirement: 模型设置接口保留默认和自定义名称

模型设置读取接口 SHALL 返回当前生效的 `model` 和配置默认的 `default_model`。更新接口 SHALL 接受可选的 `model`；省略该字段时保留现有设置，空白或与默认名称相同的值恢复默认，其余非空值保存为自定义名称。缺少模型字段的旧配置 SHALL 使用默认名称。

#### Scenario: 读取没有模型字段的旧配置
- **WHEN** 已保存配置包含 API 地址和 Key，但没有模型名称
- **THEN** 接口将配置默认名称作为 `model` 和 `default_model` 返回

#### Scenario: 保存并读取自定义名称
- **WHEN** 更新接口收到非空且不同于默认名称的 `model`
- **THEN** 接口保存该名称，并在后续读取时将其作为 `model` 返回，同时返回未改变的 `default_model`

#### Scenario: 更新时省略模型名称
- **WHEN** 更新接口收到地址或 Key，但没有 `model` 字段
- **THEN** 系统保留此前的自定义名称或默认状态

### Requirement: 主模型请求使用当前生效名称

远程主模型的健康检查和实际模型请求 SHALL 使用模型设置中的当前生效名称；没有自定义名称时 SHALL 使用配置默认名称。

#### Scenario: 自定义模型名称用于请求
- **WHEN** 用户保存自定义模型名称，健康检查或关系抽取随后发送请求
- **THEN** 请求内容中的模型名称与已保存的自定义名称相同

#### Scenario: 默认模型名称用于请求
- **WHEN** 当前没有自定义模型名称，健康检查或关系抽取发送请求
- **THEN** 请求内容中的模型名称与配置默认名称相同

### Requirement: 显式更换已配置的 Key

已有 Key 时，系统 SHALL 初始展示“已配置”和“更换 Key”操作。选择更换后 SHALL 显示空的密码输入框；取消更换 SHALL 清除新 Key 输入并恢复已配置状态，同时保留正在编辑的 API 地址。页面 MUST 不读取或显示已保存 Key 的内容。

#### Scenario: 更换后取消输入
- **WHEN** 用户编辑 API 地址，点击更换 Key 并输入新内容，然后取消更换
- **THEN** 新 Key 输入被清除，Key 状态恢复为已配置，API 地址的编辑内容保持不变

### Requirement: 保留空 Key 的现有语义

未配置 Key 时，系统 SHALL 直接显示密码输入框。保存时，空白或仅包含空白字符的 Key SHALL 表示保留现有 Key，并以文字说明这一行为。系统 SHALL 允许保存不要求 Key 的模型服务地址；Key 配置状态 MUST 不被表示为连接测试结果。

#### Scenario: 已配置 Key 且新输入为空
- **WHEN** 用户修改 API 地址，进入更换 Key 状态但未输入有效内容，然后保存
- **THEN** 系统更新 API 地址并保留已保存的 Key

#### Scenario: 服务允许无 Key
- **WHEN** 当前没有 Key，用户只填写有效 API 地址并保存
- **THEN** 系统允许提交并保持 Key 未配置状态

### Requirement: 提交前校验 API 地址

系统 SHALL 对空地址、无效 URL 和非 HTTP 或 HTTPS 地址显示字段错误，并禁止发送保存请求。服务端返回的其他地址校验错误 SHALL 在弹窗内显示，并保留所有编辑内容。

#### Scenario: 地址字段不符合要求
- **WHEN** 用户填写空白地址或非 HTTP、HTTPS 地址并尝试保存
- **THEN** 弹窗显示地址字段错误，焦点定位到该字段，系统不发送保存请求

#### Scenario: 服务端拒绝地址
- **WHEN** 服务端拒绝包含查询参数等不受支持内容的地址
- **THEN** 弹窗显示服务端错误并保留地址和新 Key 输入，允许用户修正后重新保存

### Requirement: 显式保存并防止重复提交

系统 SHALL 仅在用户提交保存操作后更新配置。保存期间 SHALL 显示等待状态、禁止编辑和重复提交，并暂停关闭弹窗。读取失败时 SHALL 禁止保存。

#### Scenario: 保存请求进行中
- **WHEN** 用户提交有效设置且保存请求尚未完成
- **THEN** 系统只发送一次保存请求，输入及取消、关闭操作暂时不可用

### Requirement: 准确表达保存结果

保存成功时，系统 SHALL 清除新 Key 输入、显示成功反馈并关闭弹窗，同时刷新服务状态。保存失败时 SHALL 在弹窗内显示错误、保留所有编辑内容并允许重试。保存后的健康检查失败 MUST 不改变已经成功的保存结果。

#### Scenario: 保存成功并继续原页面
- **WHEN** 保存接口成功返回
- **THEN** 系统关闭弹窗、清除新 Key 输入、继续原页面，并开始刷新服务状态

#### Scenario: 保存失败后修正
- **WHEN** 保存接口返回错误或无法连接
- **THEN** 弹窗保持打开，地址和新 Key 输入保持不变，错误原因可读，保存操作再次可用

#### Scenario: 配置保存成功但模型不可用
- **WHEN** 保存成功，随后健康检查报告模型服务不可用
- **THEN** 系统显示已保存结果，并由顶部服务状态表达当前不可用情况

### Requirement: 关闭确认与编辑内容清除

未保存的地址修改或非空新 Key 输入存在时，用户取消或关闭弹窗 SHALL 获得放弃修改的确认。继续编辑 SHALL 保留输入；确认放弃 SHALL 关闭弹窗、清除编辑内容并保持已保存配置。无修改时 SHALL 直接关闭。点击遮罩 MUST 不直接关闭弹窗。

#### Scenario: 关闭时选择继续编辑
- **WHEN** 用户编辑配置并尝试关闭，随后在确认中选择继续编辑
- **THEN** 弹窗保持打开，所有输入保持不变

#### Scenario: 放弃修改后再次打开
- **WHEN** 用户确认放弃修改后重新打开设置
- **THEN** 系统重新读取已保存配置，新 Key 输入为空，被放弃的内容不被恢复

### Requirement: 键盘操作与焦点恢复

系统 SHALL 支持键盘打开入口、在弹窗内访问表单及操作按钮，并将焦点限制在当前对话框内。按 Escape SHALL 使用同一关闭确认规则；保存期间 SHALL 暂停 Escape 关闭。实际关闭后 SHALL 将焦点恢复到顶部入口。

#### Scenario: 使用键盘完成编辑
- **WHEN** 用户通过键盘打开入口、编辑地址并提交保存
- **THEN** 用户可以完成整个流程，弹窗关闭后焦点回到顶部入口

### Requirement: 窄屏表单可用

弹窗 SHALL 适应桌面和窄屏窗口，地址与 Key 字段保持单列，长地址和错误信息保持可阅读。窗口宽度为 320px 时 SHALL 无水平溢出；内容较高时 SHALL 可以滚动访问所有字段和底部操作。

#### Scenario: 窄屏查看较长的配置内容
- **WHEN** 用户在 320px 宽窗口打开弹窗并查看长地址或错误信息
- **THEN** 弹窗位于窗口范围内，用户能够访问字段及保存、取消操作，页面无水平溢出
