# Proposal

## Why

文档抽取需要由网页配置的关系类型及其头尾实体类型组合约束，并完整保存原文中属于这些类型的实体。独立实体与实体类型需要成为正式结果，供网页审阅与导出使用。

## What Changes

- 建立实体类型与关系类型配置，支持网页添加、编辑、启停关系，维护实体类型定义、父类型、关系方向及允许的头尾类型组合。
- 提供指挥、协同、情报保障的默认配置；武器平台包含水面打击力量、水下打击力量、空中打击力量和长导打击力量四个子类型。
- 抽取直接使用启用的关系定义及其关联实体类型；每篇文档开始处理时确定完整配置版本，实体识别、关系抽取、校对和合并共用该版本。
- 独立抽取实体集合，保留没有参与关系的符合类型要求的实体；关系通过实体 ID 引用两端。
- 实体每批识别一次，身份判断按关联记录批量并发执行；关系按原文批次直接抽取，使用类型规则限制实体 ID，并报告实际请求完成数。九页验证文档目标耗时为 1—2 分钟，上限为 3 分钟。
- 原文引用在处理期间参与身份判断与校验，抽取服务完成后返回独立业务结构。版本 4 的结果、网页与 CSV 使用实体与关系字段，历史任务读取时转换，已有文件保持原样。
- 实体表展示名称、别名和类型，关系表显示头实体、关系与尾实体及类型。
- **BREAKING**：网页抽取流程采用可配置的类型约束，停止领域 skills 路由及其管理接口；新结果采用带版本的实体与关系结构。历史任务保持可读，历史数据缺少的信息保持未标注。

## Capabilities

### New Capabilities

- `extraction-schema-management`：网页维护实体类型与关系定义、类型组合、默认配置、保存校验及文档配置快照。
- `typed-document-extraction`：完整实体抽取、实体 ID 引用、指定关系抽取与校验、跨批次处理、结果展示导出及历史读取。

### Modified Capabilities

无。当前 `openspec/specs/` 没有已发布规格。

## Impact

- 后端：`backend/app/api.py`、`config.py`、`pipeline.py`、`skill4re_client.py`、`types.py`，新增配置存储与结构化校验模块，替换网页流程的 `SkillStore` 入口。
- 抽取：`skill4re/skill4re/service.py`、`prompts.py`、`backends.py`、`types.py` 及 normalization；复用已有模型请求适配、文档模型快照、批次调度、任务取消与 SSE。
- 前端：`App.jsx`、配置管理组件、`ResultViewer.jsx`、`StreamConsole.jsx` 及 `lib/api.js`，沿用 React、Arco Design 和页面滚动方式。
- 存储与接口：新增版本化抽取配置、`entities` 与 `relations` 结果及实体 CSV；保留任务上传、状态、结果查询和历史关系导出入口。
- 依赖：直接声明结构化校验和配置文件互斥保存所使用的第三方依赖；沿用标准 JSON 读写。
- 文档与验收：更新 `PRODUCT.md`、README、配置示例及项目说明；通过真实 API、Worker、Redis、模型、OCR 与浏览器 DOM 检查验证完整处理流程。
