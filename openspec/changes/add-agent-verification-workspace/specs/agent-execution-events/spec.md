# Spec Delta

## Purpose

让调用方在校验智能体运行期间读取完整、有序的执行事件及原文依据，在刷新页面后恢复此前的过程，并在任务结束后继续查询规划、工具调用和最终结论的对应记录。

## ADDED Requirements

### Requirement: 执行活动具有开始和结束记录

系统 SHALL 在核查阶段、任务规划、每次模型调用和每次工具调用开始时立即记录事件，并在结束或出错时记录对应事件。事件 MUST 包含文档任务编号、核查任务编号或阶段标识、时间、类型和状态；成对的调用事件 MUST 使用同一个调用编号，结束事件 MUST 提供耗时。

#### Scenario: 正在等待模型

- **WHEN** 规划或任务执行已经发起模型请求且请求尚未返回
- **THEN** 调用方能够读取该请求的开始事件，并识别模型正在处理请求

#### Scenario: 同名工具连续调用

- **WHEN** 一个核查任务连续两次调用同一个工具
- **THEN** 两次调用使用不同调用编号，各自的参数、结果和耗时可以准确对应

#### Scenario: 调用返回业务错误

- **WHEN** 工具返回动作被拒绝或证据未通过检查的信息
- **THEN** 结束事件保留返回内容并明确表示拒绝状态，页面能够区分动作被拒绝与检索没有命中

### Requirement: 事件摘要与结构化详情分别可读

系统 SHALL 为事件提供有长度上限的可读摘要，并保存工具实际返回的结构化内容和输入参数。原文、小节、页码、关系改动前后内容及删除理由 MUST 能通过事件详情读取；工具自身截断了内容时 MUST 保留截断标识。摘要截断 MUST 不破坏详情的数据结构。

#### Scenario: 原文内容超过摘要上限

- **WHEN** 工具返回的原文超过事件摘要长度上限
- **THEN** 事件列表返回截断摘要和标识，详情接口仍返回工具实际提供的完整原文及位置字段

#### Scenario: 原始工具已经截断内容

- **WHEN** 读取小节工具返回带有截断标识的原文
- **THEN** 详情保留该标识，调用方能够识别该内容的读取范围

### Requirement: 运行期间保存完整事件

系统 SHALL 在事件产生时保存记录，并为每个文档任务分配从 1 开始严格递增的 `seq`。事件 MUST 在进度快照发布之前可被读取。最近事件数量限制 MUST 不影响完整记录的查询。保存失败 MUST 向调用位置传播错误。

#### Scenario: 最近事件已经替换

- **WHEN** 核查产生超过 20 条事件，早期事件已不在最近事件快照中
- **THEN** 调用方仍能读取早期事件及其详情

#### Scenario: 页面刷新

- **WHEN** 核查仍在执行，调用方重新从 `seq` 为 0 的位置读取
- **THEN** 返回此前保存的事件，并允许继续读取后续事件

### Requirement: 按序号分页读取执行事件

系统 SHALL 提供 `GET /api/agent/<task_id>/events?after_seq=<seq>&limit=<limit>`，返回严格大于 `after_seq`、按 `seq` 升序排列的事件摘要，以及 `next_seq`、`last_seq`、`has_more` 和核查阶段状态。重复请求同一游标 MUST 不产生重复写入。游标和页大小不合法时 MUST 返回 HTTP 400，文档任务不存在时 MUST 返回 HTTP 404。

#### Scenario: 分页读取

- **WHEN** 待返回事件超过页大小
- **THEN** 返回一页事件，`next_seq` 指向该页最后一条事件，`has_more` 为真，后续请求能够继续读取

#### Scenario: 尚无新事件

- **WHEN** 游标等于最新事件序号
- **THEN** 返回空事件数组、相同的 `next_seq` 及当前阶段状态，客户端可以继续等待

#### Scenario: 请求不存在的任务

- **WHEN** 调用方请求不存在的文档任务事件
- **THEN** 返回 HTTP 404 和可读错误说明

### Requirement: 按事件读取完整详情

系统 SHALL 提供 `GET /api/agent/<task_id>/events/<seq>`，返回对应事件的元数据、参数和结构化详情。文档任务或事件不存在时 MUST 返回 HTTP 404。已经生成的事件详情 MUST 在文档处理结束后仍然可读。

#### Scenario: 查看命中证据

- **WHEN** 调用方请求一个检索原文或定位证据事件的详情
- **THEN** 返回实际命中的原文、对应小节和已有页码；缺失的位置字段保持缺失

### Requirement: 阶段结束记录最终采用的结果

核查阶段结束时，系统 SHALL 记录最终状态、任务完成度和关系改动的采用情况。工作过程中的改动 MUST 与最终结果的采用情况对应；未采用的过程改动 MUST 保留记录并明确标识。核查状态 MUST 与文档处理任务状态分别表达。

#### Scenario: 部分完成

- **WHEN** 部分任务已完成且后续执行因资源上限停止
- **THEN** 结束事件标记部分完成，保留已完成任务的结论，并标识最终采用的改动

#### Scenario: 工作过程中的改动未被采用

- **WHEN** 核查阶段最终采用核查前的关系列表
- **THEN** 相关过程事件仍可查询，结束记录明确表示这些改动未被最终结果采用

### Requirement: 保持现有记录的可读性

系统 SHALL 保留现有状态接口和结果接口中的核查字段，并在新生成的记录中增加事件版本和最新序号。历史结果只含旧轨迹时 MUST 返回已有摘要并标识详情可用性；未保存的调用开始时间和结构化内容 MUST 保持缺失。

#### Scenario: 历史任务具有旧轨迹

- **WHEN** 已保存任务只有旧格式的 `agent_result.trace`
- **THEN** 查询返回其中已有事件摘要，并明确表示哪些事件没有结构化详情

#### Scenario: 核查未开启

- **WHEN** 文档任务未开启核查
- **THEN** 事件查询返回空事件数组和未开启状态
